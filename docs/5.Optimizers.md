# COPRO vs MIPROv2: DSPy Optimizers Overview

This document provides a high-level overview and comparison of two key DSPy optimizers: **COPRO** (Coordinate Ascent Program Optimizer) and **MIPROv2** (Multi-Stage Instruction and Proposal Optimization).

## 1. COPRO (Coordinate Ascent Program Optimizer)

**Concept:** 
COPRO focuses on **Instruction Optimization**. It acts like a "Prompt Engineer" that iteratively rewrites the system prompt (instruction) to find the best wording for your task.

**How it works:**
1.  **Proposal:** It asks an LLM to generate multiple variations of the instruction (e.g., "Think step by step," "Act as an expert classifier," etc.).
2.  **Evaluation:** It runs your pipeline with each instruction against your `devset` and scores them using your metric.
3.  **Selection:** It picks the instruction with the highest score.
4.  **Iteration:** It can do this in multiple rounds (steps), refining the best instruction further.

**Best for:**
- ZERO-SHOT tasks where you want the best possible instruction but no examples.
- When you don't have enough data for few-shot learning.
- Simple tasks where a good instruction is 80% of the battle.

---

## 2. MIPROv2 (Multi-Stage Instruction and Proposal Optimization)

**Concept:** 
MIPROv2 is the "Heavy Lifter". It optimizes **Both Instructions AND Few-Shot Examples** simultaneously. It is a data-driven optimizer that finds the best combination of:
1.  Which training examples to use as demos?
2.  Which instruction works best with those demos?

**How it works:**
1.  **Bootstrapping:** It generates synthetic reasoning traces for your training data.
2.  **Proposal:** It proposes multiple candidate instructions (like COPRO).
3.  **Search:** It uses a Bayesian optimization approach to intelligently search the space of (Instruction + Set of Examples).
4.  **Selection:** It returns the optimal combination that maximizes your metric on the `devset`.

**Best for:**
- Complex tasks where "Show, Don't Tell" (few-shot) is critical.
- When you have a `trainset` of at least 10-50 examples.
- When you need to squeeze the last % of performance out of a model.

---

## Comparison: COPRO vs MIPROv2

| Feature | **COPRO** | **MIPROv2** |
| :--- | :--- | :--- |
| **Primary Goal** | Optimize **Instructions** (Zero-Shot) | Optimize **Instructions + Few-Shot Examples** |
| **Optimization Strategy** | Coordinate Ascent (Hill Climbing) | Bayesian Optimization (Smart Search) |
| **Data Requirement** | Minimal (Standard Devset) | Moderate (Needs `trainset` to pick demos from) |
| **Cost / Tokens** | Lower (Generates text prompts) | Higher (Evaluates long few-shot prompts) |
| **Output** | A polished System Prompt | A System Prompt + A curated set of Few-Shot Demos |
| **Use Case** | Quick start, simple tasks, zero-shot | Production-grade pipelines, complex reasoning, few-shot |
| **"Mental Model"** | A skilled Prompt Engineer rewriting your prompt. | A Data Scientist curating the perfect dataset and prompt combo. |

### Summary Recommendation
*   Start with **COPRO** if you are just building the prototype and want a good prompt.
*   Switch to **MIPROv2** when you have collected ~50 examples and want to maximize accuracy for production.
